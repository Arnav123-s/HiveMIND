# Read literal examples and requested calls in an English file order

This research parser reads a named Python file, function examples and requests for actual values. It recognizes selected imperative forms, changes in punctuation, line-layout instructions and report instructions before or after the examples. It normalizes only literal positional calls with JSON-compatible arguments, preserves the requested call order, and refuses recognized contradictions or unsupported metadata. The reconstructed instruction must parse to exactly the same structured values using the original module relay. The existing relay then extracts and executes unchanged candidate functions inside WASI. [Frozen parser](intake.py) · [Protocol](protocol.md) · [Original relay](../../file_relay/relay.py)

**External language test.** An independent author wrote eight valid requests and five requests to withhold without seeing the parser. We saved every first parser decision before grading. The parser extracted **0/8 complete valid requests**. It missed seven and accepted one incomplete order. That order said “In your reply, list …” before introducing the functions. The parser correctly retained its filename, functions and examples but dropped both requested calls. It withheld all five negative controls. This missing instruction would let a worker deliver only the file when the user asked for values as well. The frozen implementation has no general guarantee that it noticed all requested behavior. [Independent protocol and questions](../intake_panel/protocol.md) · [All 13 graded decisions](outside-results.json)

**What passing examples buys.** A development control passed two examples and both user queries with two different programs. The first program chosen produced the required visible lines `7` and `18`. On the additional input 10 its first function incorrectly returned 7; the second program returned 11. Both ran inside the real guest. This is direct evidence of ambiguity even when the intake accurately recovers all four literals. [Actual module sources, public outputs and additional exact case](finite-check.json)

Reproduce the parser panel from the repository root with plain Python. The scorer checks the source and panel digests, records every first extraction, and only then loads the expected results. It compares the full filename, functions, typed examples and ordered queries.

```sh
python -m training.experiments.verified_growth.delivery_audit.literal_intake.outside \
  --out /tmp/hive-module-intake
```

## Real archive results and the post-audit guard

The independent archive reviewer applied the frozen reader to all 90 original attempts at ten kinds of Python module across three generations. It recognized 10/90 attempts covering three kinds; six had been declined. Five authentic candidate files passed the explicit examples and agreed on the requested values. Each also passed all 50 subsequent private checks and its two visible output lines. This changes the archive replay from 26/90 to 31/90 attempts. Those five extra deliveries represent four distinct prompts. Six lookup-only programs also passed the public examples but failed independent grading, which limits what can be concluded at publication time. [Archive grades, resource receipts and controls](../public_examples/README.md)

After examining the missing-call failure on the English panel, we froze a separate occurrence guard. It scans the original text for JSON-compatible literal calls and compares all named argument occurrences with the parsed example and query occurrences. It refuses repeated identical calls, even when both are accounted for, to avoid assigning an ambiguous role. Its additional rules contain no English request phrases. On the known 13-case panel the incorrect partial acceptance became an abstention. Exact coverage stayed at **0/8** and all five negative requests were withheld. This is a fix measured after the failure was revealed. [Guard](lossless.py) · [Synthetic controls](test_lossless.py) · [Post-audit outside-panel decisions](guard-results.json)

On the 90 archived attempts, the guard preserved six accepted contracts byte-for-byte in their fields, removed four, and left the other eighty withheld. Of the six preserved examples, three had already received the right answer and three were declined tasks that could still recover a correct file. The guarded replay therefore reaches **29/90**, losing two of the five original recovery gains. The three retained recovery attempts represent two distinct prompts. Reusing the original grades for identical contracts required no extra model or WASI run. Every preserved case still has only bounded public evidence. [All archive comparisons](../public_examples/guard.json)

## Fully accounted repeated calls

The final post-audit control removes the blanket repeat veto while keeping exact call multiplicities. It accepts an explicit request to report the same call twice, or to report one of the demonstrated calls again, only when every original occurrence has a corresponding parsed role. The source parser still deduplicates duplicate example declarations, so an unexplained repetition leads to withholding. [Predeclared control](multiplicity-protocol.md) · [Implementation](multiplicity.py) · [Repeated-call controls](test_multiplicity.py)

This control withheld all 13 known outside-panel prompts, just as the conservative guard did. It prevented the silent omission while still extracting **0/8** complete valid requests. On the historical archive, its 10 accepted contracts matched the first parser’s contracts exactly and the other 80 stayed withheld. That retains all five correct worker-file recoveries, raising 26/90 to **31/90** across attempts and 16/33 to **18/33** distinct exact prompts with any passing attempt. It also retains all six wrong lookup-only proposed programs that passed the finite public checks. The grade comparison reused identical preexisting evidence; no fresh inference or guest executions occurred.
