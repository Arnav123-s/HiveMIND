# Can a user-provided input refute apparent agreement on a Python file?

Freeze a set of deliberately contrasting, benign module candidates across eight unrelated one-argument functions. Each request specifies a total function on a plain typed domain. Every two-worker case agrees on the printed value from a primary user example. Feed actual printed values and named source files through the ordinary post-generation handoff. In a second step accept additional literal user-supplied probe inputs (no expected values); validate their types, range, and shape against that request's declared domain. In an actual CPython WebAssembly guest invoke each available artifact independently on each admissible input. Return contradicted when two successful outputs differ in JSON type or value; return matching observations for fully matching successful outputs on at least one admitted probe; return unknown for a singleton, absence of valid probes or an execution error that cannot be independently classified. Never promote a previously unconfirmed answer, choose the first divergent value as correct, or use a mismatched input to reject a module. Publish all observed values and rejected probes.

Measure three separate outcomes: the stock accepted file/report, the same file/report subject only to a negative veto, and releases for which additional matching observations exist. Score emitted files after all decisions are written, using independently authored withheld examples for the eight public functions. Count correctly/incorrectly released, withheld, vetoed correct and vetoed wrong. An additional matching observation is bounded evidence and cannot establish complete functional correctness. Keep the original G52 jobs separate. No user-supplied secondary probes or independent peer existed there.
