# Blind transfer from English to a table answer

An evaluator writes ordinary English requests, fresh CSV inputs, and an independent SQLite query or an explicit reason a unique answer cannot be determined. The solver author receives the input and output interface and the list of broad supported operations. The exact requests, data, combinations and keys stay private until the solver and control modes are hashed. No official HiveMIND held-out exam questions, makers or keys enter this study.

Give each solver only the request and its table. A job requests one JSON value, which can be a scalar or an object mapping observed group names to quantities. A missing result or a clean refusal counts as a miss on any answerable request. On a task with genuinely insufficient information it counts as the appropriate action. Count incorrect values and runtime failures separately. Object key order and JSON whitespace do not matter. Booleans do not count as integers. A ranking that has an unresolved tie must respect any explicit tie rule. Vote counts, an internally well-formed plan and fluent text alone earn no credit.

The primary panel has six operation patterns with three independently worded requests in each. Each request uses a different field vocabulary within its pattern and runs on two independently varied table contents with the same schema. Both results must be correct for a request to pass. A pattern passes only if all three of its requests pass. Report results on all 18 requests and six patterns, alongside per-table scores. Compare operation paths with the solver's frozen teaching patterns after evaluation. Patterns that occur in training remain in the denominator, labeled familiar. This six-pattern test cannot be counted toward HiveMIND's official five-of-ten goal.

Also score three simple earlier capabilities, three answerable adjacent data questions and three questions that need clarification. The nine additional questions run on both table variants. Report these groups separately. The first tables use the same recorded request wording as the second. The material is independently authored, not real user traffic. The scorer receives keys only after each arm has emitted decisions; selectors see neither answers nor SQL. Compare the flat task baseline, simple deterministic planner and composed or learned planner on exactly the same inputs when available. Inspect any gains, regressions and new wrong answers. Log whether each answer was returned in memory or written by the solver's real CLI as a parseable JSON file.
