# Can a mechanical record preserve what file handoff actually saw?

Twelve independent synthetic scenarios cover design assets, documents, settings, two-file orders, stock records, ordered rows and a binary package. They were written without reading the candidate source, official release jobs, worker exam archives or benchmark generators. Each contains literal user text, worker messages and independently authored worker bytes. Four controls use missing work, split files, byproducts or old output. Some jobs have a single plausible answer or two workers with the same incorrect file. Correct final bytes are private until the candidate source is frozen. Neither capture nor the normal release path receives the examiner's key.

Run the stock public solo handoff using the real scratch tree, inspections, agreement, selection, ordering, copy and return. Stand in for actual inference only at the member boundary with recorded worker text and on-disk files. Compare what reached the caller's output directory and what the growth workflow's real file selection patterns would include in a diagnostic archive. Put the proposed archival capture in a separate destination. Compare recovered bytes and provenance for every occupied seat separately. No scores, reference answers, external task formulas or execution of worker source are allowed inside capture.

Count full correct caller deliveries, wrong caller deliveries, abstentions, unrequested files, complete or partial member bundles, independently stored identical pairs, and the exact regular named worker-file bytes retained before and after capture. An archived correct-but-unconfirmed candidate changes diagnostic coverage only. A singly plausible candidate, shared wrong file, or two halves from different seats cannot be credited as a new correct delivery. Ensure capture does not change public output bytes or any prior decision for any case. These controlled snapshots can identify mechanical archival losses but cannot estimate their frequency in live generations.
