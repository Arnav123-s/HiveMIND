# Can a direct model call produce a candidate outside the table interface?

Use the bare native t80 model and the ten official held-out *families*. Before anyone sees the selected questions, freeze one generic system prompt, one nonce, the actor and output parameters in settings.json. For every family, accept the first distinct prompt from the deterministic seed stream `verified-growth-native:{nonce}:{maker}:{draw}`, starting at draw zero. Exclude only exact byte-normalized SHA-256 matches to old official prompts or a previously accepted new prompt. Try at most 64 seeds per family, record all exclusions, and record any unrepresented family. This extra step matters for finite makers. There is no exclusion based on content, expected difficulty, answer, cost, grade or run outcome. Freeze a sealed anonymous request list before inference. No family label, checker, seed, task ID from the release, previous solution, adapter, routing or worked example enters the model.

One greedy non-thinking chat call per selected request, 128 new tokens maximum. No tools or network for the model. The user message is unmodified, including inline data. Use a pinned bare t80 GGUF, native CPU backend, 4,096-token context and no speculative decoding. Record raw replies (including blank, partial or wrong text), finish reason, usage, duration and any infrastructure failure. Seal *all* historical requests' new-draw outputs before any scoring. Under irrecoverable inference failure, keep existing responses, count the missing answer explicitly, and never retry a completed prompt.

The independent grader compares (a) the complete raw assistant message under the official per-question checking contract and (b) exactly that same message plus generically extracted clearly named file blocks. The report remains raw in both modes. A correct file can make a task pass only when the official contract also accepts every requested visible value. The evaluator may use the public reference website if required; separate verification unavailability from incorrectness. Run candidate Python only inside WASI. Report token-limit truncation, errors and opportunity to deliver files. This is at most one fresh job per family and does not measure the official two-out-of-three criterion, demonstrate a sustained learning gain, or estimate the advantage over a fresh multi-worker body. Hardware time excludes scheduling waits.
