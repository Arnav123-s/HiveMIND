# Frozen chronological replay and disagreement study

Use the exact published G55 and G56 all-rows archives and the repository's G55/G56 kept-body decisions. A row is eligible for self-replay only if it is a verified first/fix practice or dream program, carries an exact t80 member identity in the named kept roster or its recorded kept trunk, comes from before the cutoff, and carries no held-out evaluation source. Keep a separate count for the single current trunk. Named organ membership can span previous generations. Deduplicate exact task/program combinations and distribute the bounded reservoir across task organs and kinds using a stable hash; cap at 400. Count recent and historical eligible rows and how many can actually be distinct at fixed sampling ratios. Treat imported teacher lessons, uncredited pairs, DONE and missing lineage separately. Never execute untrusted archived code.

For a bounded CPU behavioral check, train a small conditional character model of verified Python program text. Rank the chosen and rejected programs in real historical preference pairs by mean conditional next-character log probability. Textual question features enter through a predicted task-kind bucket learned from question text; neither candidate's verdict, member name, task-maker label, seed, row order, public diagnostic, nor rejected-program text may act as positive supervision at prediction time. Freeze a 25% exact-question-hash split across the whole study before training. All held-out question strings and both of their candidate program texts are excluded from fitting. Train the base on pre-G56 retained ordinary verified programs and teacher lessons; G56 incoming rows are the adaptation stream. Build the old replay reservoir only from pre-G56 sources available at the release of G55. For equal CPU update budgets of 120 rows each, compare frozen base, all incoming, and two versus four eligible old rows for every incoming row. Use the same deterministic incoming and replay orders, wrapping only if necessary. All adaptive arms apply the same fixed forgetting factor per update; report strict pair choices, old/new coverage, ties, and opportunity cost without claiming SFT or full-program generation. Include a no-decay sensitivity control. Report every arm whether it helps or hurts. G56 was a dropped generation; its new rows are training/scoring evidence here, not a new kept model.

For T8/T10, measure what evidence the row archive actually contains for distinct workers, public checker outcomes and pre-verdict features. A selected positive/rejected pair alone does not establish a two-against-one majority, an independently checked counterexample or a controllable flip. Quantify replayable archived full-seat decisions only if their joint verdict and membership are present; otherwise report the coverage limit. Score separately on prior published experiments when relevant and identify their source populations. No generation workflow or new 8B training.

Implementation parameters fixed before scoring: normalized question SHA-256 modulo four equals zero designates evaluation; deterministic SHA-256 order within kinds for reservoir and sampling. Sparse byte trigram next-character counts use local-kind interpolation with strength 8 against a global trigram with additive 0.1 smoothing over 256 next bytes. A smoothed bag-of-words task-kind classifier trained only on base questions routes all evaluation examples. Normalize base counts to the equivalent of 120 equally weighted program rows, use exponential discount 0.98 per adaptation step and also show 1.0. A ratio with fewer than 120/3 or 120/5 new rows repeats rather than borrowing unseen evaluation. Programs stay in archive; comparison needs no code execution. Exact duplicate tasks and program text are excluded across splits; near-paraphrases may persist.

Lineage qualification tightened before scoring. The kept archive omits each member's checker receipt. Its own generator can fall back to the agreeing pair when independent verdicts are unavailable. A named emitted first/fix row carrying `agreed=false` therefore provides positive evidence of an individual checker pass: the fallback cannot emit that member. Use this provable subset for the primary verified reservoir. Count ordinary agreement-backed named rows separately, without silently labeling them independently checked. For the single-trunk data-supply check count both before and after G56 collection; simultaneous practice shard numbers do not establish time order, so no arbitrary within-capture time claims.
