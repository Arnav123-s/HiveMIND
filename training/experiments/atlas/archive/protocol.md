# Eight-cell archive and two broad exploratory lineages

This is a prospective selection protocol on historically familiar native first-token data. There are no new 8B generations. Freeze before calculating any candidate's development or terminal score.

* Reuse the island study's 60 training IDs alone. Partition the 30 excluded endpoints within each (domain, original-anchor/supplementary) group by SHA-256("archive-v1:" + question). Alternate ranks between development/test, rotating the starting side by alphabetical domain index. This leaves 15 development and 15 terminal rows, 9 original and 6 supplementary on each. Terminal labels cannot select a parent, a surviving head, an archive size, a route, a noise amplitude or a seed.
* Candidate pool starts with eight saved fits/controls: bare, the island all-60 pooled fit, and the six original individual native t80 output edits reconstructed from the public training states. Verify the native calibrations from the prior study. Give every arm 24 new broad proposals, with 18 teaching cases per proposal, one per domain-label stratum, sampled deterministically with seed and step. Each new head learns all 18 output tokens with the existing rank-four residual fit. One versus two independently starting lineages are crossed with zero versus 0.05 relative additive Gaussian perturbation to the input factor A only (Frobenius normalization). Seeds 11, 23 and 37. Each lane's first proposal starts from the bare body. Subsequent steps draw a parent uniformly from surviving champions of that lane; if none survives, draw from the current archive. Two-lane arms alternate lanes. Paired mechanisms use separate random streams for parent draw, row draws and noise; all arms have equal fitting and development-check budgets.
* Eight possible MAP-Elites cells have three behavior bits: on at least one third of each development group, does the proposal change the unrestricted first-token ID relative to bare? Groups are (coding,math), (conversation,machine learning), (engineering,physics). These are token-change descriptors, including casing. Each occupied cell retains the head with highest total normalized development correctness, retaining the earliest on ties. A bounded archive can stay partially empty.
* At the end of the same proposal stream compare the final head, the best single development head, the repertoire, and five size-matched random repertoires (seeds 101,103,107,109,113; select random distinct candidate IDs from the stream). Same-size controls compare retention conditional on the MAP-Elites proposal stream; they do not estimate a counterfactual random search process.
* Use an executable route that requires no test labels or supplied test domain. Infer a domain from nearest cosine centroid in centered frozen features learned solely from training inputs. For each inferred domain select the repertoire member with the best number correct on corresponding development inputs, falling back/tie-breaking by total development correctness then earliest ID. Freeze the candidate byte hashes, all champion/parent choices and every route before scoring. Separately report the hindsight ceiling if a perfect per-question router could always pick a correct member. Each deployed policy uses at most eight heads, one final prediction per request; the ceiling can inspect all retained outcomes.
* Report all seeds/arms, gains and losses against bare on the 9 earlier test anchors and 6 supplementary endpoints, development and test differences, stored capacities, niche occupancy and any extra correct cases. Compare the two-lineage setting with one under the same proposal count; there is no live access, interaction, novel generated task or G41 evaluation. Even favorable differences for 5% noise on this reused corpus cannot establish stochastic resonance.
