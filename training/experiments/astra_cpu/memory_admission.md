# CPU row admission and activation checkpointing

In grow's CPU training loop, `--no-checkpoint` with `HIVE_ROW_CHECKPOINT=1` selects the ordinary or recomputed transformer path per training row. With the variable unset, the trainer applies its existing static length limit and ordinary memory guard. An explicit `--checkpoint` keeps checkpointing throughout the run. The adaptive path requires a Transformers checkpointable decoder suffix. On unsupported models it logs the reason and uses fixed admission.

The ordinary path keeps activations for backward and can reuse a cached frozen prefix. When this path would consume the reserve, the trainer estimates the cost of keeping suffix inputs and recomputing decoder activations during backward. If this fits it bypasses the prefix cache for the whole update. Both choices preserve the examples, the loss, dropout RNG, and the optimizer. Layer checkpoint functions are installed once and the flag only changes when the next admitted row needs a different choice. Each row gets a fresh memory reading. After a recomputed row, a return to ordinary training requires a margin of 25% of that row's ordinary estimate, capped at 256 MiB. This prevents switching back and forth when free memory fluctuates by a few MiB near the threshold. There is no margin on first admission, on entry to recomputation, or when only ordinary fits. Initial-admission snapshots in the archive comparison therefore remain directly comparable.

## What gets counted

* Fast path starts with the existing 46 hidden-size values per token per layer, counted across the entire suffix that participates in backward. The recomputed path budgets one full active layer and two additional hidden-size values for each suffix layer, capped at the ordinary estimate.
* The head allowance covers projected tokens × vocabulary size × 16 bytes. The default projection includes the extra position produced then sliced away. When `HIVE_CHUNK_CE` actually selects a smaller Qwen3 projection, the estimator uses that same projection length.
* On a preference pair both policy sequences count toward activations. The head allowance covers both policy answers and the larger of the two sequential reference forwards. One combined check chooses a path or records a single rejection.
* Each path maintains a separate observed high-water cost per token. Admission takes the larger of the analytic estimate including the head and the measured total cost. The measured peak already includes the head.
* On a finite Linux cgroup, the opt-in ternary loader gives the kernel one read-only `POSIX_FADV_DONTNEED` hint per original model shard after conversion. Only shards opened by this load receive it. Eagerly reading the model can otherwise leave several GiB of clean source pages charged to the runner. Admission uses the subsequently measured headroom. An unavailable hint leaves the cautious guard in place.
* Available memory is bounded by the host reading and each visible finite cgroup v2 limit. Only inactive file pages left after subtracting dirty, writeback, mapped, shared and unevictable pages receive reclaim credit. Missing file statistics give zero credit. An unreadable previously detected usage counter causes a rejection.
* Opt-in training rows can reach the caller's requested maximum length. Rows that pass that ceiling still require live admission. The held-out before/after evaluation uses a single, fixed initial cap. A slice records both caps, counts for ordinary and recomputed passes, and separate learned costs.

The floors are engineering estimates calibrated from a particular model, and the watcher samples every 0.1 seconds. Short transient allocations, load from other processes, and changes in kernel cache activity can affect the result. The reserve remains active on both paths.

Run the regression suite with `python -m pytest -q tests/test_row_checkpoint.py tests/test_memory_guard.py tests/test_prefix_cache.py`. It checks optimizer and loss parity with alternating gears, preference rows and dropout, the cache and hook lifecycle, memory accounting, and a saved local ternary Qwen3 passing an otherwise excluded training example through grow's normal entry point.
