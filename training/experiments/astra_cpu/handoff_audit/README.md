## T7. Paired sequential stopping

We retrieved all ten recorded generations in G45–G55. G46 was cancelled. We compared original fresh per-task grades on exactly matching tasks in each before/after arm, verifying archive SHA-256, task IDs and prompt identity. The official grade archives also carry a code revision and kind, which had to match. In the separate Atlas work archives, the same generation/run and exact per-task prompt bytes had to match. We neither read fixed exam task contents nor called a model. G45 has one same-ID job with different prompts across the two arms, leaving 63/64 matched. The predeclared complete-cohort rule excludes it. Its legacy gate also used a two-task allowance and officially kept 45 vs 47. The remaining nine generations supply **576 matched fresh tasks**, with eight pairs of arm jobs per generation. [Frozen protocol](protocol.md) · [Additional cohorts](extension.md) · [Per-seed source IDs and SHA-256](paired.json)

The handoff specifies error targets but does not define the two hypotheses needed to reproduce a likelihood ratio. We froze an illustrative 60:40 vs 40:60 conditional chance of a new-body win among discordant pairs. At the requested 5% boundaries the run needs a net lead or deficit of at least eight to stop after four or six seeds. A second rule stops only when every possible outcome on the remaining tasks preserves the final fresh verdict. Both used all eight seeds in **every generation**. The largest interim lead or deficit was two. [Source](replay.py) · [Every interim look](results.json)

## Reproduce

From the repository root, run these commands with its installed Python environment. The first needs only the standard library and the included per-seed ledger. The second loads the existing delivery code. Neither calls a model or network.

```sh
python training/experiments/astra_cpu/handoff_audit/replay.py --out /tmp/fresh-replay.json
python -m training.experiments.astra_cpu.handoff_audit.python_contract
```

To reconstruct the ledger, provide Atlas PR #122's `pulse/artifacts.json` and the original content-addressed ZIPs with `--index` and `--work`. Each further `--grades gNN=DIR` contains the sixteen original `gate-{before,after}-{1..8}.zip` files and an `index.json` whose `archives` list contains GitHub's artifact `name`, `id` and `digest` fields. Their IDs and hashes are in the published ledger. The collector compares prompt identity in memory and exports only counts, source identities and the mismatched task ID. [Source manifest for Atlas](https://github.com/Arnav123-s/HiveMIND/pull/122)
