# Three chronological replay updates

Freeze this protocol before computing preference scores. Use the four original all-rows artifacts for G53 through G56. Initialize a conditional byte-trigram ranker and request classifier on pre-update G53 positives. Use the identical archived PR 132 likelihood function in all arms. Fork the same G53 state to fresh-only, current 2:1, current 4:1, and matched-source diagnostic arms. Spend 30,000 program-target bytes per update, truncating the final row. Run G54, G55 and G56 in order. Promote or roll back each arm according to the historical release decision, so a dropped G54 cannot silently seed G55. Use fixed random seeds 17, 42 and 91 and no fitted parameters. Use no decay as the principal measurement, and simulate 0.98 inherited evidence retention per consumed row as sensitivity. Grades, accepted/rejected preference labels and future rows must never enter a live routing decision. Train with constant subject loss in this proxy.

Primary old panel: Fix a preference per normalized question from the G53 archive with SHA-256 modulo four equal to one (the prior single-stage study used zero). Resolve alternatives by the hash of the unordered two programs. Reserve this entire fold across all stages. Remove both candidate programs of every old panel item from all training. At each stage also score first-seen G54/55/56 preference questions on the reserved fold and remove test pairs with either program in any training candidate pool through that stage. Report the fixed old denominator, gains and losses on the same questions, and fresh denominator. Cumulative practice preference records need not establish both final actors' answers separately.

Independent secondary measurement: Use old G50–52 fresh-gate work archives and G54–56 fresh-gate work archives for later assessments, with the fixed archive manifest from PR 132. Read them only after every candidate and update sequence has been planned and fitted. Require exact seat and actor identification, independently graded final answers, an unambiguous unique script producing each answer in that seat and at least one positive and one negative distinct script for the same normalized prompt. Resolve duplicate prompts/pairs by program hash. Reject exact task overlaps and either program overlap across all eligible training data. Publish counts and limitations if this subset is small. Neither gate programs nor labels enter the simulated model or the hive.

Before collecting new outcomes, cost accounting in the previous run showed that replay occupied 14,875/30,000 bytes at 2:1 and 8,311/30,000 at 4:1. Uniform source row counts can overshoot their intended share of the byte budget. Also, fresh-only and replay shared one sampler RNG per run, so inserting old subjects can perturb fresh order. Diagnostic comparisons use the same independent fresh-row order in every arm and the same independent old-row order in both dosing variants. Compare row-dose versus target-byte-dose using those streams. This separates the two effects; a source-independent stream or byte dose stays experimental regardless of outcome. Publish every arm and seed. Changes to the production sampler require evidence on a later unseen cohort. This survey cannot demonstrate 8B retention or three consecutive accepted native generations.
