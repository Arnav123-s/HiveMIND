# Prospective three-update retention pilot

Start from the published G55 rank-32 trunk. Keep the complete G55 body as the source of old verified practice solutions. Run three local T80 CPU fits in sequence. Each fit gets two distinct new G56 teacher rows from one family and one old G55 member row. New rows are fresh relative to the G55 release. All three fits use their actual G56 generation label in the trainer. Their numbered order describes this experiment only.

Use the public practice families for normalizing names, converting Markdown tables to CSV, and filling missing CSV values, in that order. In each family select the two lowest canonical row SHA-256 values among G56 first-turn teacher lessons whose normalized prompt is absent from G55 and the cumulative held-back training subset. If any selected reference solution fails its check, publish the failure and stop. The replay candidates are the three G55 individually successful first-turn non-agreeing member programs from practice seeds 10005502, 10005503 and 10005509 in ascending seed order, each on a different question. Require a matching official practice archive digest, exact prompt and source program, actor, member number and positive individual checker verdict.

Generate five new requests from a fixed seed prefix. Two old-family anchors exercise price arithmetic and weekdays. The three target requests use disjoint examples of the three selected practice families. Reject any question overlapping G56's cumulative archive and any reserved official family. The two old checks and all three target checks are fixed across all four evaluations. Every candidate must preserve every whole-contract pass of its exact incumbent and add at least one target whole-contract pass to be accepted. A drop retains its adapter separately and starts the next fit from the incumbent. Preserve input, weight, response and checker hashes. Score first programs by running them in isolated CPython WASI and applying the original generator's checker on the host. Zero retries or choice among generated programs. A run interruption can resume at completed arms.

Pin beam-free greedy decoding, 384-token limit, first-turn SHORT orders, no prompt cache and no answer/hint in model messages. Use 2 CPU threads. For training use the regular t80 trainer, full precision on this host, one epoch, seed 56, learning rate 0.0002, accumulation one, rank 32, last 14 layers, 128-token output blocks, per-row checkpointing and the ordinary 2-new-per-1-old selector. Disable optional prior memory, prefix caching and held-back scoring on these nine preselected rows. Use no pull toward another trunk. Check all trainable tensors were inherited. Record actual unique passes, input-token counts by source, memory skips and full wall time. A two-anchor test cannot establish a population-level regression rate below 1%. This design tests an accepted-line retention policy with replay enabled, with no causal estimate of replay's effect versus fresh-only fitting.
