# Confirmation of one constrained refit

The severe loss on triplets in the first exam motivated a refit. The new router may open a bin only if the item fits in no existing bin. It was refit on original development streams. Confirmation uses a separate grader, fresh public instance sizes and new synthetic streams. The first exam remains diagnostic for this refit.

The primary outcome is the constrained router’s difference in bins from best-fit on each family. First-fit and the original frozen router also run on the identical sequences. Feasibility and compliance with the opening rule are checked independently at every arrival. The grader records occupied bins, bin inspections, family-level paired bootstrap intervals, and order-specific results.

The public sources are Falkenauer’s uniform 250-item and triplet 249-item files. Some larger public instances reuse runs of the exact item sequence from the smaller instances. The grader excludes a public instance if it shares eight consecutive original item sizes with any prior public instance of its class. It then takes the last ten eligible instances of each class in publication order. This keeps the number equal for the two classes. The streams have the source order, seeded shuffle and ascending order. Offline bounds and optima are used only for grading. [OR-Library](https://people.brunel.ac.uk/~mastjjb/jeb/orlib/binpackinfo.html)

Synthetic confirmation covers three prespecified shifts, with 16 new seeds and 144 arrivals each. One stream class contains sizes between one quarter and one half of capacity. A second begins with large items, followed by small items. A third uses items within one unit of simple fractions of bin capacity. All three orders are scored. Intervals resample the original independent instances and keep their orderings together. The first grader describes the bootstrap convention. [Original grading protocol](eval-protocol.md)
