# Does requiring an explicit decision reduce irrelevant consultations?

With the same four qualified native adapters, the original selector consulted the geometry adapter for one of six adjacent requests. The user had asked for a box's volume in litres and the numerical conversion. The updated requirement to ask for a supported decision withheld all six adjacent requests. Both code versions retained the same three definitely reachable applicable requests and one additional request on the talk branch. The science and electronics adapters had failed their initial native qualification, leaving those two positive cases unserved.

| Six applicable and six adjacent cases | Original helper, four adapters | Requested-decision helper, same four adapters |
| --- | ---: | ---: |
| Applicable, correct specialist on every possible route | 3/6 | 3/6 |
| Additional applicable, correct specialist on talk only | 1/6 | 1/6 |
| Adjacent, specialist was consulted | 1/6 | 0/6 |

Coding reached the correct edit after the subject consensus abstained. Conversation and machine learning reached theirs after matching consensus. In these three cases the talk branch would apply the label edit directly and the work branch would frame an internal consultation. The fourth, math, consulted a label edit only on the talk branch. All observations are work-order selection traces. The grader made no 8B calls and did not measure final-answer accuracy.

The same change replayed on the previous 24-case panel removed all five inappropriate consultations but also removed one of three definite legitimate consultations. The previous cases informed the decision to attempt the policy change and constitute an exploratory replay. The positive result on the fresh panel rests on a single rejected negative and needs a larger independent test.
