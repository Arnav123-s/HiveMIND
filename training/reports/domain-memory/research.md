# What to try next with shared signals and memory

**Can cells tell each other something a single cell could not infer?** Foerster and colleagues trained agents to learn a communication protocol from a shared objective. Hu and colleagues showed why a convention learned with one partner can fail with another. HiveMIND’s earlier two-sensor experiment got both decisions right on 96.6% of fresh cases using one byte per sender, against 96.8% with both raw inputs. The ordinary-language pair solved three of twelve context-dependent requests with the real history and none with shuffled or absent history. The next small experiment should hide a different necessary fact from each cell, freeze the partners, swap one sender, and score actual answers. That directly tests the user’s idea of a shared language between specialists. [Foerster et al.](https://arxiv.org/abs/1605.06676) · [Hu et al.](https://proceedings.mlr.press/v119/hu20a.html) · [Sensor study](../rule_lab/hive-telepathy.md) · [Request study](signals/README.md)

**Which requests benefit from consulting a specialist?** Mozannar and Sontag train a decision about when to defer using the expert’s actual errors. On HiveMIND’s fresh 30-request panel, requiring two routers to agree kept seven correct referrals, withheld an eighth, and prevented zero errors. A future router could learn from paired final-answer outcomes under the ordinary route and specialist route. Charge both arms the same inference budget and record abstentions, latency and errors. A subject label alone cannot tell whether a specialist will help. [Mozannar and Sontag](https://proceedings.mlr.press/v119/mozannar20b.html) · [Prospective confirmation](signals/consensus/README.md)

**Which lessons should survive a generation?** LoRA makes small weight updates separable from the base model. Gradient Episodic Memory gives a method for testing proposed updates against prior tasks. Claude’s independently recorded t17 experiment found that short instructions alone and the hive engram each scored 16/18 on familiar tasks. In a separate HiveMIND experiment, two model-written corrections enabled 24/24 new deposit calculations where zero or one donor delivered none. Preserve the verified program immediately. Before promoting a weight edit across the wider hive, compare the real edit, no edit and an unrelated edit with identical prompts, then rerun older skills and a new task family. [LoRA](https://arxiv.org/abs/2106.09685) · [Gradient Episodic Memory](https://arxiv.org/abs/1706.08840) · [t17 control](../../../docs/RESEARCH.md#8-do-the-hives-memories-help-measured-on-one-stream-2026-11-18) · [Native correction experiment](../verified-learning/native-lessons/README.md)

**Can two learned conventions disagree without interfering?** Mitchell and colleagues’ SERAC stored edits in memory and trained a classifier to decide which questions each edit covered. They evaluated intended and unwanted changes across question answering, fact-checking and dialogue. In one question-answering experiment, their balance of edit success and unwanted changes held up through 75 simultaneous edits. The hive’s local ML audit edit improved 2/4 to 4/4 on one two-letter convention. A proposed test would teach two teams opposite X/Y codes for the same findings, then freeze the models. Compare current selection with a scope classifier trained on earlier examples. Grade unseen paraphrases, requests naming the other team, and unrelated X/Y questions. A gain requires more correct in-scope answers at the same or lower number of incorrect changes elsewhere. [Mitchell et al., ICML 2022](https://proceedings.mlr.press/v162/mitchell22a.html) · [HiveMIND’s four paired probes](growth/graph-safe-grade.json)

**Can a failed program teach the next repair?** Le and colleagues’ CodeRL trained a critic to distinguish compilation errors, runtime errors, failed tests and passed tests. Execution feedback guided training and resampling. The complete system reached 63.0% pass@80 on the separate MBPP benchmark, a result measured with up to 80 generated candidates. The hive’s scheduling attempt exposed two different failures. Fixing an input-format error revealed a resource-capacity violation, and the resulting solver still delivered zero feasible schedules on five projects. A proposed CPU experiment would give a frozen writer one repair attempt per new problem. Compare a plain pass/fail signal, the first violated public constraint, and a failure description shuffled across problems. With equal token and execution budgets, count complete programs passing a separate checker on unseen projects. If the real constraint description only improves the visible examples, the hypothesis fails. [Le et al., NeurIPS 2022](https://arxiv.org/abs/2207.01780) · [HiveMIND scheduling results](../verified-learning/scheduling/README.md)

**When is a second worker worth the wait?** Snell and colleagues found that the best allocation between sampling, revision and verifier-guided search varied with problem difficulty on MATH. Their revision strategy surpassed best-of-N sampling at about a quarter of its test-time compute in that setup. They tested both an estimate of difficulty derived from known answers and one available without them. On the hive’s practical panel, two workers computed the correct classifier recall while the user’s request still timed out. A proposed trial would allocate a fixed pool of second-worker calls using only evidence available after the first attempt, such as a missing required file or a failed public check. Compare that policy with a random allocation of the same calls, under identical deadlines and total token caps. Score final answers delivered on time, break out easy and hard requests, and count a timeout as a failed delivery. [Snell et al.](https://arxiv.org/abs/2408.03314) · [HiveMIND practical panel](answers/README.md)
