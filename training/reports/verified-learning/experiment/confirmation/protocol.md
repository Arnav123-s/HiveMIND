# Independent confirmation of learned program edits

This panel was designed from the request to test aggregation, comparisons, decoded data, distracting edit sites, distribution shifts, correct originals and other faults. The author had seen the packaging module and the names and import lines of the repair-learning module. The author did not read the implementation body, training donors, the first evaluation panel or its results before freezing these files. This is a deliberately composed capability check, not a random sample of actual users.

There are 20 distinct contracts. Each has one original draft, 5 public examples, 7 qualification cases and 16 private jobs. The groups contain 3 aggregation contracts, 4 boundary contracts, 2 distracting-site contracts, 1 ambiguous public sample, 2 distribution or representation shifts, 2 decoded-dictionary contracts, 3 other faults and 3 already-correct controls. These labels describe the faults, not which edits a particular implementation supports. Each task's qualification and private inputs are disjoint from its public inputs and each other. A reference function written separately from the draft supplies the expected value. For the lecture chairs task, two one-site edits fit every public example, but the qualification cases and all 16 jobs distinguish them. For the darkroom task, a nested JSON string requires decoding even though the outer object is already decoded.

Use the same frozen development banks and baseline arms used for the original experiment. Score identical drafts, inputs and independent expectations in every arm with one model draft and at most two proposed edits. Copy each arm's initial bank into an independent directory before every task, and discard subsequent learning. Only publicly supplied rows can influence draft selection. Qualification answers can admit or withhold the selected source. Each call receives only inputs for the 16 private jobs; private answers stay in the external grader. Keep errors, refusals and timeouts in the denominator. Do not change corpus, implementation or budgets after opening scores.

Primary endpoint is successful tasks out of 20. Count a success only if the chosen method passes all seven qualification rows and delivers 16 exact private results. Also count correct individual deliveries, wrong individual deliveries and withheld jobs, with denominator 320 for each arm. For alternatives, compare paired outcomes by task, identifying wins, losses, ties and identities. Distinguish newly solved originally faulty contracts (out of 17) from preservation of three correct contracts. For unchanged controls, also report whether selected source bytes match the original when trace permits. Report selected-draft qualifications (out of 20), attempted and accepted edits when present, failed qualifications after a public pass, incorrect delivered outputs, model calls and elapsed work as available. Report each group's numerator and denominator. A score on 16 private jobs from one contract does not supply 16 independent contract observations.

A deterministic preflight ran the 20 original drafts alone against their own reference functions. They matched 19 of 100 public rows, 25 of 140 qualification rows and 59 of 320 private cases. Only the three original control drafts passed all public and qualification rows and all 16 private jobs. A system that checks and releases only these original drafts would therefore return 48 correct private results, withhold 272, and solve 3/20 contracts. The extra 11 raw private matches on two faulty drafts should not be reported as checked deliveries.

Files are generated with Python's standard library by running `python make_panel.py`. The recorded seed is 719263844. The runner may read corpus.json. keys.json is for the independent scorer and must never enter prompts or repair selection. The corpus, keys, generator and protocol have separate SHA-256 digests in SHA256SUMS.
