model files — but a birth **overwrites** the incumbent serving file
of the same name, so unlinking deleted the serving specialists
instead of restoring them:

- `coding/swarm/models/bug-off-by-one-index-model.json` — gone

## Root-cause fix (factory/growth_cycle.py)

- New `_snapshot_model_files()` / `_restore_model_files()`: every
  cycle variant (run_cycle, run_cycle2, run_cycle3) now snapshots
  the pre-cycle bytes of every target child model file (persisted
  under the run's `snapshots/models/`) before any birth attempt,
  and `_rollback` restores incumbents **byte-for-byte**; only a
  genuinely new child file is removed. The rollback lineage event
  now records `restored` vs `removed` separately.
- Regression test: `factory/tests/test_growth_rollback.py` —
  simulates adoption + rollback over pre-existing model files and
  asserts byte-for-byte restoration (plus the legacy no-snapshot
  unlink fallback). This test would have caught the bug.
- Full factory suite after the fix: **78/78 pass** (76 existing +
  2 new).
