# Gate 3′ — implemented in the growth cycle (2026-11-12)
**Muse's work, Muse's side.** Implemented before cycle 8 (cron ~22:50 PT) per the
revised spec in `factory/reports/e007-retrocheck-2026-11-12.md`.

## The gate

For each child, after the dual pristine gate passes and before the cycle's registry
rewrite makes the birth final, the FULL serving path — composer + the waking-dream
refresh a birth triggers, run in-memory exactly as production runs it — is measured
over the say_dev 216 pool (`factory/say_dev.json`, dev only; the sealed set is never
spent here), child vs parent. Adoption is blocked if either fires:

- served total falls (any fall, judged in exact item counts), or
- served clean recall falls by ≥ 1 dev item, even when the total is flat or rising
  (a compensated clean loss is the demonstrated failure signature).

A rejection never touches serving state: the two files a birth writes (child model,
composer_config routing) are restored from byte snapshots taken immediately before
the attempt; `registry.json` and `waking-dream/results.json` are never written for a
blocked child. No rollback path is involved — rollback remains only for post-adoption
verification failures of kept births. Targets are gated independently: each child's
parent scorecard is measured against the composition current at its own gate, so a
sibling birth already kept in the same cycle is part of the next child's parent state.

## Why this layer (the evidence)

The E-007 retro-check REFUTED the originally proposed raw-composer dev gate on the
cycle-6/7 records: on every composed surface measured, raw totals never fell (cycle 6
sealed raw 0.4722 → 0.4722; cycle 7: 0.5 → 0.5). Both serving regressions lived in the
waking-dream refresh: cycle 6 served sealed 0.8611 → 0.8056, entirely clean recall
(0.8182 → 0.6364, −2 items); cycle 7: 0.8611 → 0.8333, clean −1 item, defect classes
identical. Gate 3′ measures the layer where the regressions demonstrably occurred.

## Bookkeeping (so the next retro-check is computable)

- Child model bytes are snapshotted into the run dir (`gate3/<child>.json`, sha256 on
  the attempt record) BEFORE the gate decides — kept or blocked.
- Both scorecards land on the attempt record and in lineage (`gate3_prime_kept` /
  `gate3_prime_blocked`): served totals, served per-class recalls, and the raw composed
  per-class recalls before (parent) and after (child) — the before-state cycle 6 lacked.

## Where

`factory/growth_cycle.py`: `_gate3_pre_state`, `_gate3_registry` (in-memory parent
sandbox — one member's bytes substituted), `_gate3_scorecard`, `_gate3_verdict`,
`_gate3_prime`; hooked into all three cycle paths (`run_cycle`, `run_cycle2`,
`run_cycle3` — the cron/auto path is cycle3). One reading worth naming: the spec's
clean rule says "even when the total is flat"; it is implemented as ≥1-item clean fall
blocks regardless of total direction, since a rise elsewhere masking a clean fall is
the same hiding pattern as the flat case.
