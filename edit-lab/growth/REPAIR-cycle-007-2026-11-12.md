# Repair of the cycle-007 rollback crash — 2026-11-12

## What broke

Growth cycle 7 (run_cycle3, the cron's auto path) produced two
births that passed the dual gate — wrong-operator/expression
0.9500 vs parent 0.8500, off-by-one/index 1.0000 vs parent
0.9500 — but serving verification FAILED: battery overall
0.941 → 0.9375, sealed bug-pattern 0.8611 → 0.8333 (31/36 →
30/36; clean recall 0.8182 → 0.7273). The rollback then crashed
before restoring anything:

    NameError: name 'model_snapshots' is not defined
    (factory/growth_cycle.py, run_cycle3's _rollback call)

so both regressed children stayed serving, the registry and
waking-dream results kept their post-adoption state, and no
cycle-007 record was written (the ALERT file is the record).

## Root cause

The cycle-006 repair added the pre-cycle model-file snapshot
(`_snapshot_model_files`, persisted under the run's
`snapshots/models/`) to **run_cycle only** — in fact the patch
landed there three times (a triplicated block) and in neither
of the other two cycle paths. **run_cycle2 had the identical
latent defect**: it also passed `model_snapshots=...` to
`_rollback` without ever taking the snapshot. Cycle 7 was the
first rollback ever attempted on the cycle3 path, so it was
the first to hit the missing name.

## Code fix (factory/growth_cycle.py)

- `run_cycle3` and `run_cycle2` now take the pre-cycle model
  snapshot with the same cycle-006 helpers
  (`_snapshot_model_files` / `_restore_model_files`), persisted
  under each run's `snapshots/models/`, before any birth
  attempt. `run_cycle`'s triplicated snapshot block was
  deduplicated to one.
- Regression tests: `factory/tests/test_growth_cycle_rollback_paths.py`
  — integration tests that drive the real `run_cycle2` and
  `run_cycle3` with stubbed training/battery/judge/audit: a
  birth overwrites both incumbents, the served battery
  regresses, and the cycle's own rollback must restore the
  incumbents byte-for-byte from the snapshot the cycle itself
  took. On the pre-fix code both tests raise the NameError.
- Full factory suite after the fix: **80/80 pass** (78 existing
  + 2 new).
