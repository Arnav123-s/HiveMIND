### FABLE-CAND-03 · Members-first routing (soloists first, specialists as fallback) — routed from Fable's side
- **source:** Fable's side commit `61fb325`, seed 9007 clean sitting (never looked at before, nothing learned, code db8b8d0, all three arms run at the same time): **members first 10/16 in 179 min; roles alone 9/16 in 178 min; members alone 9/16 in 69 min.** Fable's side changed its `ask.yml` default to members-first (`members: "2"`; `"0"` = roles alone) on this evidence. Seed 9006 table: members alone 8/16 in 181 min (code baabc10). Full candidate text: `bitnet-lab/mill/FABLE-CANDIDATES.md`. Pool merge round 2 routed this entry to this file rather than the mill pool.
- **mechanism:** Generalist members attempt the whole task first, with the specialist/role pipeline only taking what members cannot confirm. On Fable's side that matched the full pipeline's score at ~40% of the wall time (members alone) and beat it by one task when combined (members first).
- **change:** `factory/serve.py` routing — add a members-first arm: a generalist member answers first; the composer/specialists engage only on items the member cannot confirm. Dev-only composition test alongside (not replacing) the learned-say work. **Fable's own caveat, carried from the same record:** on "mend a program," both members ran the same broken program and *agreed on its wrong output* — agreement between members who used the same method is **not independent verification**. Any members-first composition on Muse's side therefore needs a verification path that does not share the members' method — here: execution verification through the waking-dream layer, which checks by running the code rather than by asking another member.
- **judged by:** Dev-only head-to-head first (members-first vs the incumbent route on the dev pool): must match incumbent accuracy at materially lower wall time, or beat the accuracy. Serving adoption only through the full battery: overall must beat 0.941 with no section regression. Shadow-first until then.
- **kill test:** On dev, if members-first loses accuracy to the incumbent route — or if its same-method agreement failure appears (members agreeing on outputs the execution layer refutes) at a rate the different-method gate does not catch — retire.

### PL-003 · Cross-niche sparring: one niche's generator attacks another niche's judge
- **source:** Every generator in the factory only attacks its own niche: `factory/dream_gen_niches.py` `niche_generators()` registers exactly two subjects (contract-judgment, commit-type), and `factory/dream_gen.py` attacks only the bug composition. ### PL-004 · Drill budgets as a governed resource: a drill that cannot state its spend does not run

### PL-006 · Member-vs-member round-robin: the 16 bug members drill each other's restraint
- **source:** The bug composition's members are individually strong and jointly weak: seat binary accuracies run 0.88–0.96 on dev (spawn-mining record) while the raw composed sealed accuracy is **0.4722** against the served path's 0.8611 — the loss is in how members fire on *each other's* classes, and every existing drill trains a member on its own positives. Mutable-default stands as the extreme case: a single seat, judge n=7 on the primary split, "near-anecdotal everywhere" (`factory/COMPOSITION-RESEARCH.md`).
- **mechanism:** A round-robin restraint drill: each seat's execution-proved positives are posed to every *other* seat as negatives, producing a 16×16 cross-fire matrix (seat × foreign class false-fire rate) on dev families. The drill diet for a seat is then built from its worst cross-fire cells — foreign positives it wrongly claims — paired with its own positives (PL-008's pairing), so practice buys *restraint* (not firing on a sibling's defect) rather than more recall on an already-strong binary. The matrix is re-measured after each round; a seat with no cross-fire cell above 0.05 sits the round out.
- **change:** `factory/dream.py` — `composed_eval()` gains the cross-fire pass over the injectable registry; `factory/compose_research.py` — `a1_preds()`'s harness reports the matrix beside its standing approach rows; drill diets flow through `run_dream_subject()`'s existing per-class retrain path, gates unchanged.
- **judged by:** Dev first: the worst cross-fire cell per drilled seat must fall, with that seat's own-class recall held (no recall-for-restraint trade beyond 0.01). Serving only via PL-005: Gate 3′ on `say_dev`, then the battery — raw composed sealed must rise above 0.4722's standing baseline *and* served sealed must beat 0.8611 with overall > 0.941; a restraint gain that only moves the raw number is reported as exactly that.
- **kill test:** The first matrix: if every off-diagonal cell is already ≤ 0.05 on dev, cross-fire is not the composed loss — the Phase D margin diagnosis (PL-002) stands unchallenged, and the round-robin is retired before any retraining spend.

### PL-007 · Dream-pool inventory: the pool as perishable stock, topped up on a rotation — not generated per crisis

### PL-008 · Clean-sentinel paired drills: no defect drill without its clean twin in the room

### PL-009 · Spaced re-drill of mastered bands: what the thermostat steps past, the regimen steps back to
- **source:** The thermostat only moves forward: `factory/dream.py` sets `MASTERY = 0.90` and steps the edge band up when a band is mastered, and nothing ever re-probes a mastered band. - **kill test:** After 7 rounds, if no mastered band has ever dropped more than 0.02 on re-probe, decay at mastered bands is not occurring at this timescale — double the intervals once; if a further 7 rounds still show nothing, retire the re-probes and record mastered bands as stable.

### PL-011 · Drill-exam hygiene: one-shot drill exams, hash-registered, demoted to diet only after the next exam is minted
