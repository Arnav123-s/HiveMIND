# E-001 — Waking-in-the-loop say fit: dev fixed, sealed still lost
**Muse's work, Muse's side** (2026-11-12). Spec: `bitnet-lab/mill/CANDIDATES-E.md` E-001.
Background: `factory/reports/learned-say-2026-11-12.md` (the raw-verdict fit, shadow at
sealed 0.8056 vs incumbent 0.8611, the whole gap clean recall) and
`factory/reports/e007-retrocheck-2026-11-12.md` (cycles 6/7 regressed in the same place:
the waking layer's clean gate reading margin scale, raw totals flat).

## Verdict

**SHADOW — the new fit does not promote, serving is unchanged.** The in-the-loop fit did
exactly what it was supposed to do on dev — dev serving-path accuracy 0.6759 → **0.7083**,
dev clean recall 0.8571 → **0.9286**, measured on the real path and reproduced
answer-for-answer by an exact simulator — and it still lost the sealed set, **0.7500 vs
the incumbent's 0.8611**, worse than the old fit's 0.8056. E-001's prediction (sealed
≥ 0.8472 if the collapse was a fit-objective mismatch) is **refuted**: the objective was
not the whole problem. Fitting on dev-path outcomes fixes dev; the dev surface and the
sealed surface disagree inside the waking layer, and the sealed disagreement is not
visible from dev at all.

## What was run

1. **Verifier census** (`factory/e001_verifier_cache.json`, 216 rows): per dev item, the
   config-independent facts — seat margins, all five verifier outcomes, the clean
   verifier's positive outcome — computed once, under a hard-timeout subprocess protocol.
2. **Exact simulation** of `WakingDream.answer()` from the cache (climb order,
   thresholded verification, `v_clean`, the ≤ 0.5 clean-win gate, composer fallback),
   then **coordinate ascent** on simulated dev-path accuracy — same grids and
   strict-improvement discipline as the original fit — from two starts (uniform, old say)
   × two objectives (pure accuracy; accuracy-then-clean-recall). All four lanes converged
   to the **same** fit.
3. **Real-path judgment**: all four configurations (incumbent, uniform, old fit, new fit)
   run through the actual `WakingDream` on all 216 dev items, hang-safe.
4. **Sealed, exactly once**, through `run_battery._eval_bug_path` (the standard battery
   path), only after the new fit beat the old fit on the real dev path.

## A finding the census surfaced first

**The wrong-operator verifier does not terminate on 4 of the 216 dev items**
(items 184, 188, 198, 209 — while-loop shapes from the swarm dream corpus): ≥ 37
CPU-seconds and counting where a normal verifier call is ~0.005 CPU-s, and it swallows
signal-based timeouts, so only a hard subprocess kill bounds it. Any configuration —
**the incumbent included** — hangs on those items whenever wrong-operator reaches the
climb (all four configs hang on exactly those 4 items). The sealed families don't contain
the shape: the incumbent's sealed number reproduced exactly (0.8611), so the battery has
never seen this. It is a serving-path robustness fact independent of the say, recorded
here because E-001 is the first work that ever ran the waking path over the dev pool.
In the fit, a config that climbs a timed-out class scores that item wrong (a path that
never answers has not answered correctly).

## Reading

- The fit-objective mismatch was real and is now closed as an explanation: on the surface
  the fit can see, in-the-loop fitting is strictly better. The sealed loss survives it,
  so the remaining cause sits in the dev↔sealed relationship itself — 216 dev items,
  however honestly judged, do not price what the sealed 36 reward inside the waking
  layer. This is the E-007 pattern from the other direction: layers whose local metrics
  are green while the composed judgment differs on the surface that counts.
- For the queued family: **E-002** (clean-floor constraint) loses its premise — a fit
  that *wins* dev clean recall by 5 items still loses sealed clean by 2, so a dev clean
  floor would not obviously protect sealed clean either. **E-003** (margin-scale vs
  direction, no refitting) is now the sharp instrument: it can separate "the say points
  the wrong way on sealed clean code" from "sealed reads margin scale differently" using
  the existing fits, this census machinery included.
- The verifier-timeout shape deserves its own line of work regardless of the say: a
  serving verifier with an unbounded search is a hang waiting for the wrong input.
