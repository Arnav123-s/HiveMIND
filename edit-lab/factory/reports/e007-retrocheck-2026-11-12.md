analogues plus the mechanism, not on a dev-pool rerun.

  0.9500/0.9566. Served sealed 0.8611 → 0.8056 (31/36 → 29/36): clean 0.8182 → 0.6364 (−2 items).
- **Cycle 7** — gates: expression 0.9500 vs 0.8500 (phase-3); index 1.0000 vs 0.9500. Served sealed

## Where the regression lived: the waking refresh, not the raw composer

Cycle 6's record separates the layers explicitly:

- `sealed_raw_composed`: raw before **0.4722**, raw after **0.4722**.
- `waking_dream_refresh`: acc **0.8056** at raw_composed_acc 0.4722, per-class clean **0.6364** —
  the refresh measurement *is* the regressed serving number.

A birth triggers a waking-dream refresh: the verification layer is rebuilt over the new
members, and its clean-win gate reads margin *scale*. The children changed the margin scales
the verifier keys on; the raw composer's verdicts never moved in total. This is the learned
say's shadow verdict in a second costume ("combination changes move the verification
behaviour, not just the verdict" — `learned-say-2026-11-12.md`). E-007's premise is half
right: clean-recall, yes; "visible in the raw path," no — visible only in the *served* path.

One partial exception: cycle 7's raw per-class recalls did shift under the flat total —
clean 0.6364 → 0.5455 (−1 item) while wrong-operator rose 0.3 → 0.4 (+1 item), netting 0.5 → 0.5
(cycle-7 judge file vs the repair judge files, which re-measured the restored parents at the
same 0.5). So a *per-class* raw floor might have caught cycle 7; for cycle 6 the raw per-class
before-state was never recorded (totals only), so that variant is untestable for cycle 6.

## What the records cannot establish

- **The say_dev counterfactual itself.** Neither cycle's children were ever run on the
  216-item dev pool, and the child model bytes no longer exist: cycle 6's were unlinked by
  the buggy rollback (REPAIR-006 documents the full-VM copy hunt — negative); cycle 7's were
  overwritten in place by the repair rebuilds (the serving files now hash `fdd7f27f…` /
  `5c8f50ff…` = the rebuilds, verified for this check); both cycles' run snapshots hold only
  composer_config / registry / waking_dream_results — no model files (the root cause of both
  repairs). No dev evaluation was attempted for this check because there is nothing left
  to evaluate.
- **Whether a serving-path dev gate would have fired.** It measures the layer where both
  regressions demonstrably occurred, but no child was ever measured on dev through the
  served path, so its retro verdict is *cannot tell from records* — it is a prospective
  fix, not a retro-proven one.

## Patch SPEC — Gate 3′ (revised; spec only, nothing implemented)

The gate worth adding is E-007 moved one layer down: judge the **full serving path on dev**,
per child, before adoption.

1. **Where.** In the growth cycle's adoption sequence, after the dual pristine gate passes
   for a child and *before* the registry rewrite makes the birth final — replacing today's
   arrangement where the only composed check is the post-adoption sealed battery + rollback.
2. **What is computed** (per child, against the current composition, including any sibling
   birth already accepted in the same cycle):
   - Install the child in a sandboxed serving config; run the serving path exactly as
     production does — composer **plus the waking-dream refresh a birth triggers** — over
     the say_dev 216-item pool (`factory/say_dev.json`, contamination-filtered). Record
     total accuracy and per-class recalls → *child serving-dev*.
   - Identical run with the parent installed → *parent serving-dev* (compute once per
     cycle, cache in the cycle record).
   - Record raw composed totals both ways as a by-product (diagnostic only).
3. **Thresholds — block the birth if either fires:**
   - child serving-dev total < parent serving-dev total (any fall; 1 item = 0.0046 at n=216), or
   - child serving-path **clean recall** falls by ≥ 1 dev item even when the total is flat
     (a compensated clean loss is the demonstrated failure signature of both cycles).
4. **On failure.** The child is not born; serving state is never touched, so no rollback
   exists to go wrong. The rejection, with both scorecards, is written to lineage and the
   cycle record; the cycle's other target proceeds independently (today both children are
   verified as a bundle — that coupling is part of how two good births became one bad
   serving state in cycle 6, and how cycle 7's crash stranded both).
5. **Bookkeeping the spec also requires** (so the next retro-check is computable):
   raw per-class recalls recorded before *and* after every birth (cycle 6 lacks the
   before-state), and child model bytes snapshotted into the run directory before adoption
   (extending the post-repair incumbent snapshot to children).

Cost: two serving-path dev runs (216 items) + one waking refresh per candidate birth —
small against the cycle's training grid, and it spends dev, not the sealed set.

## Bottom line

Keep E-007's instinct — births need a composed gate before serving, and the sealed battery
should not be the routine tripwire — but aim it at the served path, not the raw composer.
As specified, the raw gate would have waved both regressing cycles through, because on
every composed surface anyone measured, the raw score never fell. The regressions lived
entirely in the verification layer's response to new members, and that is the layer
Gate 3′ measures.
