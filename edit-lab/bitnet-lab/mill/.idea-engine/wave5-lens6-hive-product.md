### NX-002 ★ · Classify abstention: when the margin is thin, the hive says "I don't know"
- **source:** Both runtimes compute the evidence and the front door discards it: `TinyNet.run()` returns `evidence: "margin {margin:.2f} over {n} feature(s)"` and `TernSpecialist.run()` returns `"ternary margin {margin:.2f}"`, but `factory/serve.py` `_serve_impl()` passes the raw `out` through and `hive.py` `_show()` prints only ANSWER + artifact for classify calls. Result: a classify niche answers its argmax at *any* margin — the only abstention in the product today is the no-features case (`ok: False, output: "unknown", gap: "no-features"` in both runtimes) and, one niche over, bug-pattern's "flagged unverified" fallback. This is not H-002 (confidence routing *inside* the bug composition); no classify niche has any threshold at all.
- **mechanism:** Promote the already-computed margin into structured provenance, fit one abstention threshold per niche on that niche's held/screen pools (never battery items), and below it serve the existing no-features shape — `ok: False, output: "unknown", gap: "low-margin"` plus the would-be answer and its margin, so the user sees "I don't know (it leaned X, margin 0.31)" instead of a confident coin-flip. Thresholds live in run state beside `factory/learned_say.json`, so a bad fit degrades to today's always-answer behaviour, exactly as the say state does.
- **change:** `factory/serve.py` `_serve_impl()` classify branch — parse/attach `margin` + `runner_up` to provenance and apply the per-niche threshold; `~/workspace/edit-lab/hive.py` `_show()` — print the abstention as NO ANSWER with the lean named; thresholds fitted by a small script alongside `factory/learned_say.py`'s fit path.
- **judged by:** Shadow first (threshold computed, logged in `serve_log.jsonl`, answer still served): on each niche's held pool, the abstained subset's would-be accuracy must be materially below the answered subset's, and answered-subset accuracy must beat the niche's standing held-out (secret 1.0 is exempt — a niche at ceiling needs no abstention and gets none). Serving adoption per niche only if the battery, run with abstentions counted as wrong, still reads ≥ 0.941 overall with no section regression.
- **kill test:** Per niche, on its held pool: if accuracy does not rise monotonically as the threshold sweeps up from 0 (thin-margin answers are not actually the wrong ones), the margin carries no doubt-signal for that niche — retire abstention there and record it; do not ship a threshold that only reduces coverage.

Nothing in the product meets him at that moment.
- **mechanism:** A product verb, not a new model: split the target into lines, run the existing secret-line specialist over each (one `ServingHive` load, see NX-008), and report only flagged lines as an extraction-shaped result — `path:line: verdict (margin)` — reporting line numbers and verdicts, never echoing the flagged content back. Exit code is the product: 0 = nothing flagged, 1 = at least one secret verdict, so it can gate a `git push` wrapper or a share step. Low-margin flags ride NX-002's abstention as "review" items, distinct from hard flags.
- **change:** `~/workspace/edit-lab/hive.py` — new `scan` subcommand (file or directory, text files only, size-capped); `factory/serve.py` unchanged (scan composes `serve()` classify calls); `~/workspace/edit-lab/USAGE.md` — the pre-push example.

- **kill test:** If scan's per-line verdicts disagree with the single-call verdicts on the same lines (chunking/context changing answers), or benign-corpus hard flags exceed zero after the margin split, the verb manufactures either misses or alarm fatigue — retire it; the per-line niche stays the product.

### NX-008 · Batch mode: load once, answer many — `hive.py batch <niche>` over stdin / a file
- **source:** Measured this pass: one `secret` call 9.99s wall with 0.34s user CPU; one `commit` call 6.79s wall / 0.22s user; `jobs` 0.53s. The model work is milliseconds of CPU — each CLI invocation pays the full process start + `ServingHive.load()` (the serve-time audit over every registered artifact, all 16 composition members included) for a single question. Every realistic product use above (NX-003 scan, NX-004 review, screening a diff, a log, a day of commit messages) is many questions, so the per-call load *is* the product's latency.
- **mechanism:** Amortise, don't weaken: batch mode loads and audits exactly once — the full strict audit, unchanged (this is not HV-008's lazy per-entry verification, which changes what is checked; batch changes how often) — then serves one item per input line, emitting one answer line per item in input order, each with compact provenance (artifact + margin where NX-002 lands). A phase timer (`load / audit / model-load / serve` wall times printed to stderr on `--timing`) makes the load cost a standing measurement instead of an anecdote.
- **change:** `~/workspace/edit-lab/hive.py` — `batch` subcommand reading stdin or `--file`, one `ServingHive` instance for the run; `factory/serve.py` untouched except optionally exposing the phase timings its load already spends.
- **judged by:** Parity first: a 50-item mixed batch (drawn from held pools, not battery items) must reproduce the 50 individual CLI answers exactly, verdict and artifact. Speed second: wall time per item in batch vs the single-call median measured the same day, target ≥ 5× improvement; audit still runs once per batch invocation and a corrupted-artifact copy still refuses the whole batch (fail-closed preserved).
- **kill test:** If parity fails on any item (batch state leaking between items) or the per-item wall gain is under 2× (the wait lives somewhere batching cannot amortise — e.g. per-call model reload inside `serve()`), retire the verb and file the phase-timing breakdown as the finding for whoever attacks the load path next.

### NX-010 · `--why` receipt on every answer: margin, runner-up, and the niche's battery slice, printed where the answer is
- **source:** The trust data exists and is scattered: the margin is computed per call and discarded (NX-002's source), the runner-up class is computed inside `_scores()` / `scores_X()` and never returned, held-out rides in provenance, but the battery slice — the number that actually governs promotion — appears only in `hive.py jobs` / `status`, a different command from the one that gave the answer. USAGE.md's promise is "every answer names the artifact that produced it and the score that artifact earned"; in practice the answer names the artifact and a held-out number, and stops.
- **mechanism:** Display only, zero behaviour change: a `--why` flag (and a one-line default short form) that renders what the serving path already knows — margin, runner-up class + its score gap, features fired, artifact held-out *and* battery slice, substrate — as a receipt under the ANSWER line. ### NX-011 · `hive.py try`: paste anything — the right niche claims it, or all of them abstain
- **source:** The front door demands Arnav remember 8 niches, their verbs, and which text belongs to which — USAGE.md is a six-job catalogue he must hold in his head before the hive is usable at all, and the measured traffic says he doesn't: `factory/serve_log.jsonl` (~500 lines) is overwhelmingly battery / growth-cycle self-calls, not a person asking questions. Discoverability, not accuracy, is the binding constraint on "usable by him" (his second test).
- **mechanism:** A routing verb built from abstention, not a new router model: run the pasted text past every classify specialist, normalise each margin by that niche's own held-pool margin distribution (a percentile, never the raw margin — fp and ternary scales are not comparable, the lesson of H-008's calibration failure), and let the top niche answer *only* if its percentile clears a fitted bar; otherwise the verb answers "no niche claims this" and lists the two closest niches with their leans, so the miss itself teaches the catalogue. Bug/contract (code-shaped inputs) enter the same contest via their existing paths when the text parses as code.
- **change:** `~/workspace/edit-lab/hive.py` — `try` subcommand composing existing `serve()` calls; per-niche margin-percentile tables fitted on held pools and stored beside `factory/learned_say.json` as run state (stale/missing table → that niche simply cannot claim, degrading to today's explicit verbs).
- **judged by:** Routing test built from the niches' own held pools, shuffled and stripped of labels: `try` must route ≥ 90% of items to their own niche's answer (matching the direct verb's verdict), and on out-of-catalogue text (prose paragraphs, shell commands, recipes) it must claim nothing ≥ 90% of the time. Direct verbs are untouched; battery 0.941 is not at risk by construction and is re-run to prove it.
- **kill test:** If cross-niche percentile normalisation cannot separate the catalogue (held items claimed by the wrong niche above the 10% bar after fitting), pasted-anything routing is not safe at this margin quality — retire `try`, keep the percentile tables as NX-010 receipt context.

### NX-012 · `--json` on every verb: the hive as a callable step in Arnav's own automations
- **source:** `hive.py` speaks only human text: `_show()` prints ANSWER / served-by lines, exit codes are an undocumented patchwork (0 answer, 1 no-answer, 2 serving-refused, 3 status-unavailable), and `serve()`'s structured dict — which already contains output, provenance, evidence, gap — is discarded at the print layer. Meanwhile his automations multiply (cron reports, n8n installed as his primary automation tool, the Slack agent house): every one of them that might want a hive judgment must either screen-scrape prose or import factory internals.
- **mechanism:** One flag, one truth: `--json` emits the `serve()` result dict verbatim (plus the verb's exit code semantics, documented in USAGE.md as a small table), for every verb including `jobs` and `status` (whose renderers already build structured state in `factory/status.py` `collect_status()`). No second computation path — the JSON is the object the human output was rendered from, so the two surfaces cannot drift.
- **change:** `~/workspace/edit-lab/hive.py` — `--json` global flag + exit-code table; `~/workspace/edit-lab/USAGE.md` — the automation example (a cron/n8n step calling `hive.py --json secret '...'` and branching on `ok` / `output`).
- **judged by:** Golden parity: for every battery item and every verb, the `--json` output's answer fields must equal the human output's answer in the same session, and a small consumer script (jq-only, no Python imports from the lab) must be able to answer "was that a secret, and which artifact said so" from the JSON alone. Exit codes verified per row of the new table.
- **kill test:** If any verb's JSON and human outputs disagree on any golden item, there are two truths and the flag is retired until they are one code path again — a machine interface that can drift from the human one is worse than none, because his automations will believe it silently.
